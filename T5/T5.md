## 2. 従来のTransformer（およびBERT等）との違い

これまでの対話で整理した、T5の構造的な思想や従来のモデル（特にBERTなどの派生型）との決定的な違いをまとめます。

### 2.1. タスク専用ヘッド（追加層）の完全撤廃
* **従来のモデル（BERT等）：** 分類、抽出型QAなど、解きたいタスクが変わるたびにモデルの最後尾に「タスク専用の全結合層（Linear層）」などをDIYで追加・付け替える必要がありました。
* **T5：** モデルのアーキテクチャを一切変更しません。デコーダの最後から出力される768次元のベクトルを、全語彙数（32,128次元）の確率に変換する標準のLinear層が最初から組み込まれており、これをどんなタスクでもそのまま使い回します。

### 2.2. 全タスクの「Text-to-Text」化（出力形式の統一）
* **従来のモデル：** 分類タスクなら「各クラスの確率分布」、QAタスクなら「文脈中の正解開始・終了位置（インデックス）」など、タスクごとに異なる数学的な形式で答えを出力していました。
* **T5：** あらゆるタスクを「テキストを入力して、テキスト（文字列）をゼロから生成する」という一つのパラダイムに統一しています。分類なら「positive」、抽出型QAなら「富士山」という結果を、純粋な自然言語の文字列として生成します。

### 2.3. ハードウェア計算効率を優先した語彙次元のパディング
* **従来のモデル：** トークナイザが持つ辞書の単語数に合わせた語彙サイズ（出力層の次元数）をそのまま使用するのが一般的です。
* **T5：** 辞書サイズは特殊トークンを含めて約32,100個ですが、TPUやGPUなどのハードウェア行列計算において最も並列処理スピードが速くなる「128の倍数」の法則に従い、出力層の次元数をあえて **32,128** にパディング（ダミー拡張）して設計されています。

## 3. Transformerとのモデルの違い（数学的な違い）

T5は初代Transformer（2017年の「Attention Is All You Need」）のEncoder-Decoder構造をベースにしていますが、数学的な計算プロセスにおいて、より効率的で精度の高い現代的なアーキテクチャへとアップデートされています。



### 3.1. 絶対位置から「相対位置エンコーディング（Relative Positional Encoding）」への変更
* **初代Transformer：** 入力データの初期段階で、各トークンのベクトルに「サイン・コサイン波」による絶対的な位置情報（絶対位置エンコーディング）を足し合わせていました。
* **T5：** 入力時に位置情報を足すことをやめ、Attentionを計算する（$QK^T$ の内積をとる）直前に、トークン同士の「相対的な距離」に基づく学習可能なスカラー値（バイアス）を加算する方式を採用しました。Bに関しては、(32,1)の大きさで、距離が近いものには(0,1,2..)それぞれ値が個別に与えられますが、ある程度距離が離れたところはグルーピングされています。

  * **数式の違い：**

    初代Transformer: $\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$

    T5: $\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}} + B\right)V$
    （※ $B$ はトークン間の相対的な距離によって決まる学習可能なバイアス行列）



### 3.2. Layer Normalizationの簡略化（RMSNormの採用）
* **初代Transformer：** 標準的な Layer Normalization を使用していました。これは入力の「平均」を引き、「標準偏差」で割るという処理を行います。
* **T5：** 計算コストを削減するため、平均を引く処理を完全に省略した **RMSNorm（Root Mean Square Layer Normalization）** を採用しています。平均がゼロであると大胆に仮定し、二乗平均平方根（RMS）のみでスケーリングを行います。数学的に簡略化されているにも関わらず、精度が落ちないことが証明されています。
  * **数式の違い：**

    T5のRMSNorm: $y = \frac{x}{\text{RMS}(x)} \circ w$ 

    （※ $\text{RMS}(x) = \sqrt{\frac{1}{d} \sum_{i=1}^d x_i^2}$ 。平均 $\mu$ を引く項が消滅している）

### 3.3. バイアス項（Bias）の全廃
* **初代Transformer：** Q、K、Vへの線形変換（Projection）や、Feed Forward Network（FFN）の計算において、$y = Wx + b$ のようにバイアス項 $b$ が含まれていました。Layer Normalization にも学習可能なバイアスが存在します。
* **T5：** モデル内のすべての Linear層 および Normalization層 において、**バイアス項 $b$ を完全に削除**しています（$y = Wx$ のみ）。これにより、モデルの表現力を落とすことなく、無駄なパラメータ数とメモリ消費を削減しています。

### 3.4. Pre-LN（Layer Normalizationの適用位置）
* **初代Transformer：** Attention機構やFFNの「後」に Normalization を適用する Post-LN 構造でした（$x + \text{Sublayer}(x)$ の後に正規化）。
* **T5：** 勾配消失を防ぎ、学習を安定させるため、AttentionやFFNの計算の「直前」に Normalization を適用する **Pre-LN** 構造を明示的に採用しています。

## 4. 事前学習（Pre-training）に関して

T5の事前学習は、インターネット上の膨大なテキストデータを用い、人間が正解ラベルを作らなくてもAIが自力で学習を進める**「自己教師あり学習（Self-supervised Learning）」**の形式をとります。

### 4.1. NSP（Next Sentence Prediction）の完全廃止
* **BERTの場合：** 「文Aの次に文Bが本当に続くか？」を予測させるNSPというタスクを取り入れ、入力時に「0と1（Segment Embeddings）」で文の境界を教えていました。
* **T5の場合：** NSPは学習のノイズになるとして**完全廃止**されました。モデルへの「0と1」の入力フラグも撤廃され、シンプルに「つながった長いテキスト」としてエンコーダに流し込み、AI自身のAttentionの力だけで文脈を把握させます。

### 4.2. 独自の穴埋めタスク「Span Corruption」
BERTの「Masked Language Model（MLM）」からさらに進化した、T5独自の穴埋め手法です。

* **BERTとの違い（置換ルールの撤廃）：** BERTにあった「15%のうち、80%を[MASK]、10%を別の単語、10%をそのままにする」という複雑なフェイント処理は行わず、問答無用で特殊トークンに置き換えます。
* **Span（連続した塊）の置換：** 1単語ずつ隠すのではなく、「ランダムな長さの連続した文字列（Span）」をひとまとめにして、1つの特殊トークン（`<extra_id_X>`）に置き換えます。これにより、AIは「何文字隠されているか」を自力で予測し、出力の長さをコントロールする能力を獲得します。

### 4.3. 具体的なデータの流れ（ABCDEFGの例）

元の文章を `A B C D E F G` とし、毎バッチごとのデータローダ（DataCollator）によってランダムに **`B C`** と **`F`** の2箇所（2つのスパン）が隠されたとします。

このとき、モデルに入力される「3点セット」は以下のようになります。

**① エンコーダ入力（隠された問題文）**
隠されたスパンごとに、順番に `<extra_id_0>`、`<extra_id_1>` という特殊トークンが割り当てられます。
* `A <extra_id_0> D E <extra_id_1> G </s>`
*(※ `B C` が `<extra_id_0>` に、`F` が `<extra_id_1>` にまとめられ、最後に終了トークンの `</s>` が付きます)*

**② ラベル（AIが最終的に出すべき正解）**
エンコーダで開けられた穴の番号と、そこに本来入るべき文字列だけを並べ、最後に「穴埋め完了」の合図を出します。元の文章全体（A〜G）を復元するわけではありません。
* `<extra_id_0> B C <extra_id_1> F <extra_id_2>`
*(※ 最後に `<extra_id_2>` を出すことで、「これ以上埋める穴はない（終了）」ということをAI自身に学習させます)*

**③ デコーダ入力（訓練時のTeacher Forcing用）**
デコーダが1ステップずつ予測を学習できるように、正解ラベルの先頭にスタート合図（T5の場合は `<pad>`）をくっつけ、全体を右に1つずらした「カンニングペーパー」を作ります。
* `<pad> <extra_id_0> B C <extra_id_1> F`

---

**【学習のメカニズム】**
AIは、③のデコーダ入力を少しずつ見ながら、①のエンコーダ入力（文脈全体）をCross-Attentionでカンニングし、②のラベルを予測します。もしAIが「穴に入る文字数」や「終了合図を出すタイミング」を間違えると、Cross-Entropy Lossによって巨大なペナルティが与えられ、正しい文章の長さと文脈を学習していきます。

## 5. ファインチューニング（転移学習）と多様なタスクへの対応

事前学習で「言語の基礎体力」と「文章を自由に生成する力」を身につけた後は、特定のタスクを解かせるための再訓練（ファインチューニング）を行います。T5の最大の発明は、このファインチューニングの手法を**すべてのタスクで完全に統一したこと**です。

### 5.1. どのようなタスクに対応できるか？
T5は「テキストを入れて、テキストを出す（Text-to-Text）」という枠組みに落とし込めるタスクなら、**事実上どんなものでも対応可能**です。
* **生成系タスク：** 翻訳（英語から日本語へ）、長い文章の要約
* **抽出系タスク：** 質問応答（QAタスク）、文章中の固有表現抽出
* **分類系タスク：** 感情分析（ポジティブ / ネガティブ判定）、スパム分類、文章の類似度判定

### 5.2. タスクを切り替える「プレフィックス（指示語）」
従来のモデル（BERT等）のように、タスクごとにモデルの頭に「分類用の全結合層」などを追加・変更する必要は一切ありません。
代わりに、入力文章の先頭に**「タスクを指示する短い文字列（プレフィックス）」**をくっつけるだけで、圧倒的なパラメータ数を持つAIの脳内回路（Attention）を「要約モード」や「翻訳モード」に切り替えます。

### 5.3. 具体的なデータの入り方（学習時）
ファインチューニング時のデータの流れは、事前学習の時とアーキテクチャは同じですが、**穴埋め記号（`<extra_id_X>`）は一切使いません。** 人間が読んで意味が通じる純粋な自然言語の文字列だけを入出力します。

**【例1：要約（Summarization）タスクの場合】**
* **エンコーダ入力：** `summarize: 吾輩は猫である。名前はまだ無い。どこで生れたか... </s>`
* **ラベル（最終的な正解）：** `名前のない猫である。 </s>`
* **デコーダ入力（Teacher Forcing用）：** `<pad> 名前のない猫である。`
*(※ `summarize:` というプレフィックスを見て、AIは「全体を短くまとめるんだな」と理解します)*

**【例2：感情分析（Classification）タスクの場合】**
* **エンコーダ入力：** `classify: この映画のストーリーは最高に面白かった！ </s>`
* **ラベル（最終的な正解）：** `positive </s>`
* **デコーダ入力（Teacher Forcing用）：** `<pad> positive`
*(※ 分類タスクであっても、確率値ではなく `positive` という「文字列」を直接生成させます)*

### 5.4. 訓練（Training）の仕組みは事前学習と同じ
ファインチューニング中に行われている計算（Lossの出し方）は、事前学習と全く同じ **Teacher Forcing（教師強制）** による1つズレの予測です。

1. デコーダは入力された `<pad>` 等を手掛かりに、エンコーダの文脈（プレフィックス＋本文）を Cross-Attention でカンニングする。
2. 次に続く「文字列（例：`positive`）」を予測する。
3. もし予測が外れたら、事前学習と同じく Cross-Entropy Loss でペナルティを与え、モデルの重みを微調整する。

この「モデルの構造を1ミリも変えず、入力の先頭に呪文（プロンプト）を添えるだけ」という暴力的なまでにシンプルなアプローチが、現代のChatGPTなどの大規模言語モデル（LLM）におけるプロンプトエンジニアリングの原点となっています。

## 6. T5論文における主要な実験と知見（限界の探索）

T5の論文の真の価値は、新しいモデルを提案したことだけでなく、「あらゆるアーキテクチャ、学習手法、データセットを徹底的に比較実験し、自然言語処理の『最適解』を実証した」ことにあります。ここでは、その膨大な実験から得られた決定的な結論をまとめます。

### 6.1. アーキテクチャの比較（なぜEncoder-Decoderなのか？）
* **実験内容:** 従来の「Encoder-Decoder型（T5のベース）」「Encoderのみ（BERT等）」「Decoderのみ（GPT等）」のネットワーク構造を比較。
* **結論:** Text-to-Textの汎用的な枠組みにおいては、**Encoder-Decoder型が最も高い性能**を示しました。文脈全体を双方向から一度に読み込むEncoderと、その情報を見ながら自己回帰的に予測するDecoderの役割分担が、多様なタスク（特に要約や翻訳など）において圧倒的に有利であることが実証されました。



### 6.2. 事前学習の目的関数（どう穴を隠すのが最強か？）
* **実験内容:** BERTのMLM（単語ごとの予測）や、文章の並び替え（Deshuffling）など、複数の「教師なし学習のタスク」を比較。
* **結論:** 連続した文字列を1つの特殊トークンに置き換える **Span Corruption（連続スパンの隠ぺい）が、計算効率と精度の両面で最も優れている**ことが判明しました。また、文章全体の「約15%」の文字をターゲットにし、平均して「長さ3トークン」の塊で隠す設定が、学習のスイートスポットであることも特定されています。

### 6.3. データセットの質と量（C4データセットの誕生）
* **実験内容:** Wikipediaのような整ったドメインのデータと、Webから無作為に集めた巨大なデータセットで学習効果を比較。
* **結論:** データの「量」も重要ですが、それ以上に**「質（クリーニング）」が決定的な差を生む**ことがわかりました。Googleはこの実験のために、Web上のノイズ（プログラムコード、メニュー表、不適切なテキストなど）をヒューリスティックに徹底排除した超高品質な巨大データセット「**C4 (Colossal Clean Crawled Corpus)**」を新規に構築し、これがT5の高い精度の源泉となりました。

### 6.4. ファインチューニング手法の比較
* **実験内容:** モデルの全パラメータを更新する「フル・ファインチューニング」と、一部の層だけを追加・更新する「Adapter」などのパラメータ効率化手法を比較。
* **結論:** 計算コストやメモリはかかりますが、結果として**「全パラメータを更新する（フル・ファインチューニング）」のが最も高い精度を出す**という、身も蓋もない（しかし強力な）事実が確認されました。

### 6.5. モデルのスケーリング（精度を上げる一番確実な方法は？）
* **実験内容:** 「学習ステップ数（データ）を増やす」「アンサンブル（複数モデルを組み合わせる）」「モデルのサイズ（パラメータ数）を大きくする」のどれが最も性能向上に寄与するかを検証。
* **結論:** 同じ計算リソースを追加して精度を押し上げるなら、**モデル自体のサイズ（パラメータ数）を巨大化させるのが最も確実かつ劇的に性能が上がる**ということが示されました。T5-11B（110億パラメータ）という当時としては規格外の巨大モデルが作られたのは、このスケーリングの法則に基づいています。
