# 画像処理の基礎を学んでいく

## 概要
本ドキュメントは、画像処理の基礎に関して、まとめたもの。

## 1. 画像の基本分類

画像データは、コンピュータ内での表現方法によって大きく**「ビットマップ画像」**と**「ベクタ画像」**の2つに大別されます。

### 1.1 ビットマップ画像（ラスタ画像）
* **データ構造**: 画像をピクセル（画素）と呼ばれる微小な点の集合（2次元または3次元の行列）として表現します。各ピクセルは、色や輝度を表す数値を持っています。
* **メリット**: 写真や写実的なイラストなど、複雑な色合い、グラデーション、繊細なディテールをリアルに表現することに非常に優れています。
* **デメリット**: 画像を拡大すると、ピクセルそのものが大きく表示されるため、「ジャギー」と呼ばれるギザギザやボケ（モザイク状の粗さ）が発生し、画質が劣化します。
* **画像処理における位置づけ**: OpenCVなどの画像処理ライブラリで扱うデータのほとんどは、このビットマップ画像を行列（NumPy配列など）として展開したものです。

### 1.2 ベクタ画像
* **データ構造**: 点の座標、それらを結ぶ線（数式）、塗りつぶしの色、曲率などの「数学的な演算パラメータ」として画像を記録します。
* **メリット**: ディスプレイ上でどれだけ拡大・縮小、あるいは変形を行っても、その都度数式に基づいて再計算（レンダリング）されるため、画質が一切劣化せず、常に滑らかな輪郭を保ちます。
* **デメリット**: 写真のように数千万もの異なる色が複雑に絡み合う画像を数式で表現することは不可能なため、写実的な表現には全く向きません。
* **主な用途**: ロゴ、アイコン、フォント、CADの図面、イラストレータで作成するグラフィックなど。

## 2. 代表的な拡張子（ファイル形式）の特徴

ビットマップ画像やベクタ画像をディスクに保存する際、様々な圧縮アルゴリズムや仕様に基づいたフォーマット（拡張子）が存在します。

### 2.1 JPG (JPEG)
* **正式名称**: Joint Photographic Experts Group
* **圧縮方式**: 非可逆圧縮（Lossy Compression）
* **特徴**: 
  * 人間の視覚特性（色の変化よりも明暗の変化に敏感であることなど）を利用し、知覚しにくい高周波のデータ（細かな色の変化）を間引いて圧縮します。
  * 24ビットフルカラー（約1677万色）に対応しており、写真やグラデーションの多い自然画に最適です。
  * 圧縮率を高く設定するほどファイルサイズを劇的に小さくできますが、一度間引いたデータは元に戻せない（非可逆）ため、保存や編集を繰り返すたびに画質が劣化します。

#### 2.1.1 ブロックノイズ
* **発生メカニズム**: JPEG圧縮では、画像を「8×8ピクセル」のブロック単位に分割し、それぞれのブロックに対して離散コサイン変換（DCT）と量子化を行います。圧縮率を極端に高くすると、ブロックごとの平均的な色情報の差が浮き彫りになり、ブロックの境界線が格子状に目立ってしまう現象です。

#### 2.1.2 モスキートノイズ
* **発生メカニズム**: 文字の輪郭や、コントラストがはっきりしたエッジ部分（高周波成分が密集する場所）の周辺に発生する、偽信号によるモヤモヤとしたノイズです。高周波成分をカットしたことによって、輪郭の周囲に蚊（モスキート）が群がっているように見えることからこの名がついています（信号処理におけるギブス現象の一種）。

### 2.2 PNG
* **正式名称**: Portable Network Graphics
* **圧縮方式**: 可逆圧縮（Lossless Compression）
* **特徴**:
  * データを一切損なわずに圧縮するため、保存を繰り返しても画質が100%維持されます。
  * **アルファチャンネル（透過・半透明処理）**をサポートしている点が大きな強みです。
  * 色の境界がはっきりしたイラスト、スクリーンショット、文字を含む画像、グラフなどに適しています。写真に使用すると、JPGに比べてファイルサイズが非常に大きくなります。

### 2.3 GIF
* **正式名称**: Graphics Interchange Format
* **圧縮方式**: 可逆圧縮（LZW形式）
* **特徴**:
  * 画面内で同時に扱える色が**最大256色（8ビット）**に制限されています。そのため、写真などの保存には適しません。
  * 複数の画像を1つのファイルに含めることで、特別なプラグインなしで再生できる「**アニメーションGIF**」に対応しています。
  * 特定の1色を完全に透明にする「透過処理」が可能ですが、PNGと異なり半透明（グラデーション透過）は表現できません。

### 2.4 BMP
* **正式名称**: Microsoft Windows Bitmap Image
* **圧縮方式**: 基本的に無圧縮（Rawデータ）
* **特徴**:
  * Windows環境における標準的な静止画フォーマットです。
  * データを圧縮しないため、画質の劣化が一切なく、画像処理の実験などで厳密なピクセル値をそのまま保持したい場合に適しています。
  * デメリットとして、ファイルサイズが他のフォーマットに比べて圧倒的に巨大化するため、Web上での利用やメール添付などの配信には全く適していません。

### 2.5 SVG
* **正式名称**: Scalable Vector Graphics
* **形式**: ベクタ形式（XMLベースのテキストデータ）
* **特徴**:
  * 他の形式（JPGやPNGなど）とは異なり、中身は数式や座標が書かれたXMLテキスト（コード）です。
  * Webブラウザでネイティブにレンダリング可能で、HTML/CSSやJavaScriptから直接サイズや色を動的に制御できます。
  * レスポンシブデザインのWebサイトで、スマホでもPCでも綺麗に表示したいロゴやアイコンに多用されています。

## 3. ファイルサイズの比較と使い分け

### 3.1 ファイルサイズの比較（一般的な傾向）
同じ画像サイズ（縦×横のピクセル数）かつ同じ色数の画像を各フォーマットで保存した場合、ファイルサイズの大きさは一般的に以下のようになります。

$$\\text{BMP (無圧縮)} \\\gg \\\text{PNG (可逆圧縮)} > \\\text{JPG (非可逆圧縮)} > \\\text{GIF (256色制限)}$$

* ※ ただし、写実的な写真の場合はPNGのサイズが非常に大きくなり、逆に色数の極めて少ないシンプルなイラストであれば、PNGのほうがJPGよりも小さく綺麗なファイルになることがあります。

### 3.2 用途に応じた適切な使い分け

| 画像のタイプ | 最適なフォーマット | 理由 |
| :--- | :--- | :--- |
| **風景や人物などの写真** | **JPG (JPEG)** | 色数が多く、非可逆圧縮によるデータの引き算が最も効果を発揮するため（サイズを小さく抑えられる）。 |
| **イラスト・ロゴ（透過あり）** | **PNG** または **SVG** | 背景を透明にする必要があり、エッジをシャープに保ちたいため。拡大縮小があるWeb用ならSVGがベスト。 |
| **グラフ・スクリーンショット** | **PNG** | 文字や細い線が含まれるため、JPGだとモスキートノイズで文字が滲んで読みにくくなるのを防ぐため。 |
| **簡単な動くアイコン・バナー** | **GIF** | 手軽にパラパラマンガのようなアニメーションを実装できるため。 |
| **厳密な画素値が必要な研究データ** | **BMP** または **PNG** | 圧縮によるアーティファクト（ノイズ）の混入を防ぎ、生のピクセル行列をそのまま保持するため。 |
